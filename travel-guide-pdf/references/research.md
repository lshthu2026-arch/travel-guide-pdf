# 调研来源矩阵与事实表要求

## 原则
- 每个核心主题（路线、票务、餐厅、酒店、人流）至少 1 条可点击来源；记录“来源平台 + URL + 核实日期”。
- 直连失败的平台要如实标注“未直连，经搜索引擎摘要/转载/官方页补全”，不得假装直连。

## 来源矩阵
| 主题 | 首选来源 | 直连失败时的途径 |
| --- | --- | --- |
| 行程/口碑 | 携程攻略（you.ctrip.com）、Trip.com 社区（trip.com/moments） | 搜索引擎 site: 检索正文；转载/聚合源 |
| 小红书笔记 | xiaohongshu.com | 需登录：用搜索引擎 site: 与关键词取片段；转载平台（头条/搜狐/16fan 等）并标注 |
| 景点/活动/路线 | 目的地文旅官网（如 meet-in-shanghai.net）、景点官网 | 百度百科/票务平台补全 |
| 票价/开放/预约 | 官方小程序/官网、OTA 产品页（携程/去哪儿/KKday） | 票务聚合页、当日资讯 |
| 餐厅在营/人均/排队 | 大众点评/美团、携程美食 | 搜索引擎片段 + 转载 |
| 酒店 | 携程/去哪儿/Trip.com/酒店官方 | OTA 详情页、点评截图 |
| 人流规律 | 社区攻略、本地资讯 | 经验 + 当季提示，注明为参考 |
| 天气/假期 | 天气站（weather-atlas 等）、国务院/官方放假通知 | 官方新闻转载 |

## 事实表输出
写到 WORK/tmp/guide2/research/ 下：
- sources_platform1.md / sources_platform2.md / sources_other.md：分平台记录“标题 + URL + 摘录要点 + 核实日期”。
- facts.json：结构化关键事实（键：门票、开放、预约、班次、人均、价格、人流、天气、假期…），每条含 source 与 verified_date。
- 正文所有时间、票价、开放/预约、餐厅、酒店都必须来自 facts 并有出处。

## 常用检索词
目的地+天数+攻略、目的地+月份+自由行、景点名+门票/开放时间、地名+酒店、地名+必吃/排队、（主题页）等等；每个都注明是否为 2026 当季新信息。
